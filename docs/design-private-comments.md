# 著者限定コメント機能 設計ドキュメント

## 概要

通常の公開コメントに加え、読者が「ブログ著者だけに送る」を選べるようにする。
著者限定コメントは管理画面では閲覧できるが、承認状態にかかわらず公開サイトには表示しない。

読者に「公開されません」と案内する以上、管理者の操作ミス、プラグインによるステータス変更、
テーマ変更などが起きても公開されない構造にする。

## 用語

- **通常コメント**: 管理者による承認後、公開サイトに表示できるコメント
- **著者限定コメント**: 投稿者とブログ著者の間だけで扱い、公開サイトに表示しないコメント
- **公開状態**: `MODERATED`、`APPROVED`、`SPAM` で表す既存の確認・スパム判定状態
- **著者**: 初期実装では管理画面へログインでき、コメントを閲覧できる管理者を指す

現在のサイトはコメント管理権限を記事単位で分離していないため、初期実装でも既存の権限モデルを維持する。
将来複数著者ごとに閲覧を分離する場合は、`comment.entry.user_id` による認可を別途設計する。

## 採用方針

コメントに著者限定かどうかを表す独立した真偽値を追加する。
既存の `status` に `PRIVATE` を追加する方式は採用しない。

理由は、次の状態を独立して扱う必要があるためである。

- 公開可能か、著者限定か
- 承認待ちか、承認済みか、スパムか

たとえば、著者限定コメントであってもスパム判定や削除は必要になる。
また、Akismet や NG ワードプラグインは既存の `status` を変更するため、
著者限定指定を `status` に含めるとプラグインによって指定が失われる可能性がある。

## データ設計

### `comments` テーブル

次のカラムを追加する。

| カラム | 型 | NULL | デフォルト | 用途 |
|--------|----|------|------------|------|
| `private` | boolean | 不可 | `false` | 著者限定コメントかどうか |

既存コメントはすべて `false` とし、従来どおりの挙動を維持する。

`private` は一度 `true` で保存した後、通常の管理画面操作では `false` に戻せないものとする。
投稿者に対する「公開されません」という説明と、実際のデータの扱いを一致させるためである。
初期実装では著者限定コメントを公開コメントへ変換する機能を設けない。

### モデルのスコープ

`Comment` に用途を明示したスコープを追加する。

- `publicly_visible`: `status = APPROVED AND private = false`
- `private_comments`: `private = true`

`approved` は既存コードとの互換性のため残せるが、公開画面から直接使用しない。
「承認済み」と「公開可能」は同義ではなくなるためである。

`Entry#approved_comments` は、実態に合わせて `public_comments` へ置き換える。
移行期間中に別名を残す場合でも、関連が必ず `private = false` を含むようにする。

### 公開防止の不変条件

公開画面で表示するコメントは、必ず次の両方を満たすものに限定する。

```text
status == APPROVED AND private == false
```

著者限定コメントの `status` が、プラグイン、管理操作、データ修正などによって誤って
`APPROVED` になった場合でも、`private = true` である限り公開しない。

## 投稿画面

### 入力項目

既存のコメントフォームにチェックボックスを追加する。

```text
□ このコメントはブログ著者だけに送る（公開されません）
```

- 初期値はオフとする
- チェック時は `comment[private]=1` を送信する
- JavaScript が無効でも利用できる通常のフォーム項目とする
- 名前、メールアドレス、本文など、既存の入力要件は変更しない

非公開の意味が投稿ボタンを押す前に分かるよう、チェックボックスの近くに説明を置く。
「承認待ち」と誤解されないよう「管理者の確認後に公開される可能性はない」ことを明示する。

### 投稿処理

投稿処理はフォームから受け取った `private` をコメントへ保存する。
既存のスパム対策は著者限定コメントにも同じように適用する。

- Akismet 判定を省略しない
- NG ワード判定を省略しない
- reCAPTCHA を省略しない
- 名前、メールアドレス、本文のバリデーションを変更しない

既存プラグインが `status` を変更しても、`private` には影響させない。

### 投稿完了表示

通常コメントと著者限定コメントでメッセージを分ける。

- 通常: 「コメントありがとうございました。管理者の確認後にサイトに反映されます」
- 著者限定: 「著者限定コメントを送信しました。このコメントはサイトに公開されません」

リダイレクト先のクエリパラメーターだけを信用せず、完了メッセージの種別を安全に引き継ぐ。
少なくとも、任意の URL を開くだけで非公開投稿が完了したように誤認させない設計を検討する。

## 公開画面

次のすべてから著者限定コメントを除外する。

- 記事ページのコメント本文
- 記事ページおよび一覧ページのコメント件数
- 最近のコメント
- サイドバー、テーマ固有のコメント表示
- フィード、API、サイトマップなど、コメントを出力する機能が存在する場合
- コメントへのアンカーリンク生成元となる一覧

現在使用中の `portalshit` テーマだけでなく、リポジトリ内の全テーマを検索して確認する。
一部の旧テーマは `@entry.comments` を直接参照しているため、テーマを切り替えた場合も漏えいしないよう修正する。

安全性のため `default_scope` で著者限定コメントを隠す方法は採用しない。
管理画面や保守処理からも暗黙に消えてしまうため、公開用途の関連・スコープを明示的に使用する。

## 管理画面

### コメント一覧

- 著者限定コメントに「著者限定」バッジを表示する
- 通常コメントと見分けられる視覚表現にする
- 著者限定だけを絞り込める導線を設ける
- 本文、投稿者名、投稿日時などは従来どおり確認できる

### コメント編集

- 著者限定であることを目立つ位置に表示する
- `private` をオフにする入力欄は設けない
- 著者限定コメントでは「承認済み」を選択肢から外すか、選択しても公開されない旨を明示する
- 「承認待ち」と「スパム」の変更および削除は可能とする

モデルおよび公開スコープでも公開を防止し、画面上の制御だけに依存しない。

## メール通知

### 著者への新着通知

著者限定コメントは公開承認の作業を伴わないため、管理画面だけでは見落とす可能性がある。
初期実装では、著者限定コメントの保存成功後に記事著者のメールアドレスへ通知する。

通知内容には次を含める。

- 著者限定コメントであること
- 記事タイトル
- 投稿者名
- コメント本文
- 管理画面のコメント編集 URL

投稿者のメールアドレスは個人情報であるため、通知先を記事著者以外へ広げない。
送信失敗によってコメント保存を失敗させず、既存の承認通知と同様にエラーを記録する。

通常コメントについて著者へ新着通知する変更は、本機能の対象外とする。

### 投稿者への通知

既存の `CommentNotifier` は、コメントが承認されたときに投稿者へ公開完了を通知する。
著者限定コメントは公開されないため、この承認通知を送信しない。

著者から投稿者へ返信する機能や受領メールは初期実装に含めない。

## セキュリティとプライバシー

- `private` の判定はサーバー側で行い、CSS や JavaScript で隠すだけにしない
- 公開用クエリは必ず `private = false` を条件に含める
- 管理画面は既存のログイン・認可を通す
- ログへコメント本文やメールアドレスを新たに出力しない
- エラー画面やデバッグ出力に投稿パラメーターを露出させない
- キャッシュに著者限定コメントを含む公開ページを保存しない
- HTML 出力時のエスケープおよび本文の既存サニタイズ方針を維持する
- バックアップには従来のコメントと同様に含まれることを運用上明示する

## 変更対象

実装時には少なくとも次を変更・確認する。

| 対象 | 主な変更 |
|------|----------|
| DB migration / `db/schema.rb` | `comments.private` の追加 |
| `lib/lokka/models/comment.rb` | スコープ、不変条件の追加 |
| `lib/lokka/models/entry.rb` | 公開コメント関連の追加・変更 |
| `lib/lokka/app/entries.rb` | 投稿値の保存、完了表示の分岐、著者通知 |
| `public/theme/portalshit/comment.haml` | チェックボックスと説明の追加 |
| `public/theme/portalshit/entry.haml` | 公開コメント関連と完了表示の利用 |

## テスト方針

### モデル

- 既存コメントと新規通常コメントの `private` が `false` になる
- `publicly_visible` が承認済み通常コメントだけを返す
- 承認済みであっても著者限定コメントを返さない
- 著者限定コメントをスパムへ変更できる
- 保存済みの著者限定コメントを通常コメントへ戻せない

### 投稿

- チェックなしの投稿が通常コメントとして保存される
- チェックありの投稿が著者限定コメントとして保存される
- 著者限定でもバリデーションとスパム対策が適用される
- 投稿完了メッセージが種別に応じて変わる

### 公開画面

- 著者限定コメントの本文、名前、Gravatar、リンクが表示されない
- 著者限定コメントがコメント件数に含まれない
- `status = APPROVED, private = true` の異常な組み合わせでも表示されない
- 最近のコメントなど記事ページ以外にも表示されない
- 利用可能な各テーマで表示されない

### 管理画面

- 著者限定コメントを一覧・編集画面で閲覧できる
- 著者限定バッジと絞り込みが機能する
- 著者限定指定を解除できない
- スパムへの変更と削除ができる
- 未ログイン利用者は管理画面から閲覧できない

### 通知

- 著者限定コメントの投稿成功時だけ著者へ新着通知する
- 通知失敗時にもコメント自体は保存される
- 著者限定コメントを承認済みに変更しても投稿者へ公開通知しない
- テスト環境では実メールを送信しない

## 移行とロールバック

### 移行

1. `private = false, null: false` のカラムを追加する
2. 公開用スコープと関連を導入する
3. 公開画面の参照を公開用スコープへ統一する
4. 管理画面を対応させる
5. 投稿フォームを公開する

フォームを先に公開すると、保存先や表示制御がない状態が生じるため、上記の順序を守る。
単一デプロイの場合も、公開制御のテストを通してからフォームを有効にする。

### ロールバック

アプリケーションを旧版へ戻す必要がある場合、旧版は `private` を考慮せずコメントを表示する可能性がある。
そのため、著者限定コメントが1件でも保存された後は、単純なコードのロールバックを行わない。

緊急時は次のいずれかを先に行う。

- 著者限定コメントを安全な場所へ退避してから旧版へ戻す
- 旧版へも `private = false` の公開条件だけを残す互換パッチを適用する
- コメント表示全体を一時停止する

カラム削除は、著者限定コメントの退避または削除と、旧版で公開されないことを確認した後に限る。

## 対象外

初期実装には次を含めない。

- 著者から投稿者への返信機能
- 投稿者が後からコメントを閲覧・編集・削除する機能
- 著者限定コメントを通常コメントへ変換する機能
- コメント本文の暗号化
- 記事著者ごとの管理画面閲覧権限
- 通常コメントの通知仕様変更

## 受け入れ条件

- 読者が投稿時に著者限定を選択できる
- 著者限定コメントは管理画面でのみ読める
- 承認状態や利用テーマにかかわらず公開サイトへ出ない
- 公開コメント件数に含まれない
- 投稿後に「公開されない」ことが読者へ明示される
- 著者へ新着通知される
- 既存の通常コメント、承認フロー、スパム対策が従来どおり動作する
